# 模拟器 vs 真机：哪些东西根本验不了

**这份清单的价值在于：让你知道"在模拟器里跑通了"到底意味着什么。**

答案往往是：**意味着逻辑对，不意味着功能能用。**

## 差别最大的：文件系统

这是最容易出事的一块。

| | 模拟器 | 真机 |
|---|---|---|
| `wx.env.USER_DATA_PATH` | **你电脑上的一个真实目录**，能直接打开看 | **手机上的沙箱**，用户在文件管理器里**找不到** |
| `wx.saveFileToDisk` | 有（PC 版微信提供） | **没有** |
| `wx.chooseMedia` | 弹文件选择框 | 真的调相机 / 相册 |
| `wx.compressImage` | 有时直接跳过 | 真的压缩，而且质量策略不同 |
| 文件路径 | 长这样 `http://tmp/xxx` | 各种各样 |

**灾难性的例子**（我实际踩的）：

做了一个"下载表格到本地"的功能。模拟器里**一切正常**——文件确实生成了，
在电脑的临时目录里能找到，打开也没问题。

**真机上：用户点"下载"，然后什么也没发生。** 因为文件写进了小程序沙箱，
用户在手机的文件管理器里看不到它，在微信里也找不到入口。

**修法**：改成 `wx.shareFileMessage` —— 转发到微信聊天。
**那是手机上唯一真正可用的出口**（Android 能从转发面板存到手机，iOS 能存进「文件」）。

## 需要真机能拿到的东西

| 能力 | 模拟器 | 真机 |
|---|---|---|
| 相机 / 相册 | 假装有 | ✅ |
| 扫码 | 手动输 | ✅ |
| 定位 | 可以模拟 | ✅ |
| 蓝牙 / NFC | ❌ | ✅ |
| 传感器（陀螺仪等） | ❌ | ✅ |
| **体验版 / 正式版** | ❌ **要正式账号** | ✅ |

## API 行为差异

| API | 差异 |
|---|---|
| `wx.shareFileMessage` | **必须由用户交互同步触发**。下载之后再唤起会被拒 |
| `wx.openDocument` | 能打开的格式、是否有"用其他应用打开"入口，各机不同 |
| `wx.request` | **真机要 HTTPS + 域名白名单**（详见下） |
| 订阅消息 | 要用户授权，而且模板要审核 |

## 网络这块，模拟器和真机是两个世界

**模拟器**：勾上「不校验合法域名」就能 `wx.request` 到 `http://127.0.0.1:8787`。

**真机**：

- ❌ **不能用 IP**，必须域名
- ❌ **不能是 http**，必须 https
- ❌ **域名必须 ICP 备案**，还要在小程序后台配进白名单

**所以"本地能跑"离"真机能用"隔着一整套部署**。

**两条出路**：

1. **自建服务器 + 备案域名** —— 麻烦，备案要几周
2. **走云托管** —— 用 `wx.cloud.callContainer` 调，**不需要配服务器域名、不需要备案域名**
   （这是它最大的好处）

**顺带一个坑**：`callContainer` **单个请求限制 100KB**，
所以照片这类二进制**不能塞进请求体**，得另行走云存储。

## 真机验证清单

上真机之前，把这几条抄下来一条条过：

```
□ 用真实账号发了体验版（测试号发不了）
□ 真机上能登录 / 身份识别正确
□ 主流程从入口走到出口，全程无卡顿
□ 文件能不能真的交到用户手上（转发 / 保存）
□ 照片上传（真的拍照，不是选图）
□ 网络差的时候（切 4G、关一段时间网）会不会白屏
□ 小屏安卓上的排版（模拟器默认是 iPhone，容易漏）
□ 键盘弹起时输入框会不会被挡住
```

**最容易被忽略的是最后两条**：模拟器默认 iPhone，
**小屏安卓上的布局问题，在模拟器里完全看不到**。

## 一句话总结

> **模拟器验逻辑，真机验功能。**
>
> 凡是跟"文件存到哪""能不能被用户看见""真实的硬件/系统行为"有关的，
> **在模拟器里通过 ≠ 能用**。

这也是为什么本仓库反复强调：
**先把逻辑用跑页面代码的方式测透（快、稳、能进 CI），
再把有限的真机时间花在只有真机能验的事情上。**
